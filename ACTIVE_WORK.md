## Rules

- Register implementation work here before editing begins.
- Exactly one implementation owner per active task.
- Keep scope concise; do not paste full specifications or verification history here.
- If another active task overlaps the same files or shared resource, coordinate before editing.
- Remove completed rows after their material outcome is reflected in `STATUS.md` or the task workcard.
- A small low-risk task may use the user/agent assignment itself as the task brief; a separate workcard is required only when scope, dependencies, acceptance criteria, or risk benefit from one.

Allowed statuses:

`PLANNED` · `ACTIVE` · `REVIEW` · `CHANGES_REQUIRED` · `READY_TO_MERGE` · `BLOCKED`

Completed work is not kept here as permanent history.

## Takeover

For takeover of an existing active task:

1. Read `AGENT_CONTEXT.md`, this row, and the task instruction/workcard.
2. Inspect the task branch, current diff and relevant tests.
3. Read the previous handoff only if one exists.
4. Update the owner.
5. Continue inside the existing scope.

Do not perform a full-project recovery audit unless the active task cannot otherwise be reconciled.
